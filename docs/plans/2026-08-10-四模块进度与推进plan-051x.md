## 2. 模块④ 基础设施 —— 预防层闭环（本轮主战场）

### 2.1 根因复述（来自上一轮 §2.5）

`live_lock` 只保护「谁在用 :5000 / Bank」，**挡不住「被锁挡住的会话转头去重启 SC2」**。
3v6 训练被并行会话重启 SC2（PID 36916→33828）打断，半截报告。上一轮补了**检测层**
`env_drift()`（让被打断者知情），但**预防层**（拦在动作发起方）一直缺着。

### 2.2 预防层做了什么（`live_lock.py`）

- **`restart_guard(port, resource, actor, force)`** 判定顺序（刻意如此）：
  1. `force` → 放行，但仍报出 holder（强制 ≠ 假装没人）；
  2. 无锁 → 先扫端口连接兜底（见 2.3），无连接才放行；
  3. 我就是持有者（PID 相同 / 环境变量 token 相同）→ 放行（防**恒红**，否则没人用得了）；
  4. 持有者已死 / 超期 → 放行（与取锁回收同一口径）；
  5. 其余 → **拒绝**。
- **`assert_restart_allowed()`**：`restart_guard` 的抛异常版，被拒抛 `LiveRestartBlocked`。
- **`api_clients_on_port(port, ignore_pids)`**：`netstat -ano -p TCP` 探 `port` 上的
  ESTABLISHED 连接，排除自己 + 已死进程，返回他人客户端列表。取向**宁可误报**（漏报会毁数据）。
- **`_candidate_sc2_ports()`**：跨端口候选集 = 请求端口 ∪ 历史上出过事的 {5000,5974} ∪
  锁目录登记过的端口。`SC2_LIVE_LOCK_SCAN_PORTS` 环境变量可覆盖（测试隔离用）。
- **`_scan_foreign_connections()`**：跨候选端口并集他人连接，是 restart_guard 的兜底防误杀层。
- **CLI `can-restart [resource] [--force] [--actor X]`**：退出码 0=允许 / 4=禁止，stdout=JSON。
  给 PowerShell launcher 用（它没法 import Python 模块）。

### 2.3 端口连接兜底 —— 覆盖「自愿登记制」漏洞 + 跨端口杀伤

锁只认「接入了 LiveLock 的入口」。但 `run_live_rl.py` 的 stage6、历史 3v6 训练等**根本没接锁**，
对锁体系隐形 —— 锁目录空空，SC2 上却真有一个 ws 客户端在飞。光看锁会错误放行重启。
端口连接兜底直接问 OS：`netstat` 探到任何候选端口上有他人 ESTABLISHED 连接 → 拒绝重启。

## 3. 真机实证：预防层当场拦下「空锁目录 + 他人在飞」

本轮开工时环境状态（`netstat` / `Get-CimInstance`）：

```
TCP  127.0.0.1:5974   127.0.0.1:51832  ESTABLISHED  42756   (SC2)
TCP  127.0.0.1:51832  127.0.0.1:5974   ESTABLISHED  4128    (python run_live_rl.py --port 5974 --variant stage6-terminal)
```

即：并行会话在 **:5974 跑 stage6 live RL**，锁目录**空空**（该入口没接 LiveLock）。
对上一轮的旧实现，`restart_guard(port=5000)` 会因「无锁」直接放行 —— 然后重启 SC2 会把
:5974 的 run 一起掀了，正是 3v6 事故的根因形态。

本轮实测：

```bash
$ python live_lock.py can-restart sc2-port-5000 --actor automation-1786147261455
{
  "resource": "sc2-port-5000",
  "allowed": false,
  "reason": "blocked_by_active_connection",
  "message": "禁止重启 SC2：端口探测到 1 个他人活动连接（如 pid=4128）。..."
}
exit code = 4   # EXIT_RESTART_BLOCKED
```

**结论**：预防层在真实环境上正确拒绝了一次「无锁但他人在飞」的重启。本轮严守铁律——
只发只读探针、未杀任何 SC2 进程，:5974 的 stage6 run 不受影响。

## 4. 接入真实重启路径（kill 点）

### 4.1 `launch-galaxy-vibe.ps1`（主重启入口，已接）

原逻辑在 `[1/4]` 处**无条件** `Stop-Process -Force` 所有 SC2。新增预防层守卫：

```powershell
$liveLockPy = Join-Path $repo "tools/galaxy-vibe/live_lock.py"
$guardArgs = @("can-restart", "sc2-port-$Port", "--actor", "launch-galaxy-vibe")
if ($ForceRestart) { $guardArgs += "--force" }
& $Python $liveLockPy @guardArgs
if ($LASTEXITCODE -eq 4) {
    Write-Warning "[guard] 重启被 live_lock 预防层拦截：另一会话正占用 SC2..."
    exit 4
}
# 仅当守卫放行才杀进程
Get-Process -Name "SC2_x64", "SC2Switcher_x64" | Stop-Process -Force
```

- 探测本身失败（如 python 缺失）→ 按「被占用」保守处理，不杀（exit 4）。
- 新增 `-ForceRestart` 开关，绕过守卫（仍会在裁决里报出 holder，留下痕迹）。
- 语法 `PARSE_OK`。
