## 二C、脚本问题修复（本次新增）

### 1. LibVibeKernel.galaxy — VIBE-RUNTIME-001 Bank reload 逻辑修复

**问题**：早期实现中 WriteBankKey/WriteBankInt 每次都调用 `BankLoad`，而 SC2 的 BankLoad 是幂等的（返回已加载 handle，不重读磁盘）。连续写入时 `BankRemove+BankLoad` 会丢弃内存中刚写入的 key，最终 Bank 文件只剩最后一次写入的 key。

**修复**（`tools/galaxy-vibe/kernel/LibVibeKernel.galaxy` + 地图包同名文件）：
- 新增 `libVibeKernel_gf_ReloadBank()`：先 BankRemove 再 BankLoad（读路径使用，读取 Host 外部写入的数据）
- 新增 `libVibeKernel_gf_EnsureBankLoaded()`：仅 handle 为 null 时 BankLoad（写路径使用，保留内存中已写入的 key）
- WriteBankKey/WriteBankInt 改用 EnsureBankLoaded
- ReadBankKey/ReadBankInt 改用 ReloadBank

### 2. Galaxy `color` 保留字冲突

**问题**：`HandleVisualActorTint` 中局部变量名 `color` 与 Galaxy 内置冲突。

**修复**：`color` → `colorStr`（同文件同步修改 map 包内的 LibVibeKernel.galaxy）。

### 3. sc2_simulator 营地单位性能优化（combat.py / vision.py）

**问题**：1281 个营地单位（Player 3/5 预放置感染建筑/守卫）导致 O(N²) 性能瓶颈。

**修复**（`reference/sc2-ally-bot/src/sc2_simulator/systems/`）：
- `combat.py`：
  - 新增 `_enemies_cache`（TTL=22 loop）+ `_has_nearby_enemy_fast`（sight 范围预筛）
  - P3/P5 IDLE 单位跳过主动索敌（按原版亡者之夜"原地防守"玩法）
  - `apply_damage_breakdown` 中 P3/P5 IDLE 受击 → 进入 TARGETING 反击
- `vision.py`：
  - 视野计算降频到每 11 loop 一次（AI 决策周期 22 loop 的一半）
  - 只对 Player 1 计算视野（其他玩家视野无消费者）

### 4. M6 JSON trigger E2E 场景补齐

**问题**：M6 缺少 JSON triggers 字段端到端验证场景。

**修复**（`reference/sc2-ally-bot/`）：
